A. Give tenant & access checks one seam

Strong in-process

dashboard.ts

one interface, every router calls through it

Problem: tenant and therapist-assignment checks are hand-rolled per router, and session.ts skips them entirely — any authenticated user can read or mutate another clinic's session by guessing an id.

Solution: deepen a single access-control module that owns "does this record belong to this caller" for Child, Plan, and Session; every router calls through it instead of writing its own guard.

  • Locality: tenant bugs fixed once, not four times
  • Leverage: one interface, every router a caller
  • Closes a real cross-tenant leak at the seam

Problem: ~10 near-identical "if status isn't X/Y, throw" blocks are duplicated across session.ts and plan.ts; the schema file that looks like it should own these rules holds only types.

Solution: deepen a lifecycle module per entity — one transition(current, action) function each — that routers call before persisting.

  • Interface shrinks to one transition call
  • Transitions become testable without a database
  • Locality: legal moves defined in one place

E. Give clinicSummary's seven internal views their own interfaces

Worth exploring in-process

packages/api/src/routers/dashboard.ts:377-663

Before — mass diagram

interface: () => ClinicSummary
7 inline views: session breakdown, room utilization, therapist load, adherence, top games, consent backlog, retention — none separately callable or testable

After — mass diagram

interface: 7 named views
each view a deep, independently testable function; clinicSummary just composes them

Problem: a 280-line procedure with no arguments hides seven independent derived views, none of which can be exercised except by calling the whole procedure end-to-end.

Solution: give each derived view (session breakdown, room utilization, therapist load, adherence, top games, consent backlog, retention) its own named function; clinicSummary composes them.

  • Each view testable without the other six
  • Locality: a broken view is isolated to its own function
